# Forge MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an open-source, self-hosted Laravel app that holds a Forge API token and exposes permission-gated, secret-scrubbed Forge operations as an MCP server.

**Architecture:** Laravel 13 app from the official Livewire starter kit. A `ForgeClient` (Laravel HTTP client, no SDK) is the only path to Forge. A `PermissionEngine` resolves per-token, most-specific-wins rules. Every MCP tool extends one base class that enforces permission → calls Forge → scrubs output → writes an audit entry.

**Tech Stack:** PHP 8.3+, Laravel 13, `laravel/mcp` ^1.1, Laravel Sanctum, Livewire starter kit (Fortify + Flux), Pest, Pint, Larastan, SQLite default.

**Spec:** `docs/superpowers/specs/2026-11-03-forge-mcp-design.md` (moved into the repo in Task 1).

**Repo:** app lives in `/Users/abishekrsrikaanth/projects/Laraavel MCP/Code`; GitHub `abishekrsrikaanth/laravel-forge-mcp` (public). All paths below are relative to `Code/`.

## Global Constraints

- Forge API base `https://forge.laravel.com/api`; Bearer token; `Accept: application/json`; all resource paths under `/orgs/{org}`; server/site ids are integers; JSON:API responses (`data.id`, `data.attributes`).
- Pagination: cursor (`page[size]`, `page[cursor]`, `meta.next_cursor`). Rate limit 60 req/min.
- Never call the real Forge API in tests — `Http::preventStrayRequests()` in `tests/Pest.php`.
- Fresh token = only `view` and `view_logs` allowed (global). Everything else denied until a rule allows it.
- Most specific rule wins: site > server > organization > global. No matching rule = denied.
- `restart_services` rules only at global/organization/server scope; site rules never apply to it.
- Capabilities are independent; none implies another.
- Organizations not exposed on the Forge connection are denied for everything.
- All text returned to an agent goes through `SecretScrubber`, except `get_site_env`.
- Secrets are never written to the audit log, app log or any page: Forge token, `.env` values.
- Tunables live in `config/forge-mcp.php`: `poll_timeout` 20 (s), `list_cache_ttl` 60 (s), `secrets_cache_ttl` 600 (s), `log_tail_default` 200, `log_tail_max` 1000, `audit_retention_days` 90, `scrub_min_length` 8.
- No Claude/AI attribution in commits or PRs.
- Commit messages: Conventional Commits.

## Review Focus

1. **Forge token revoked or expired after setup** → every tool returns "Forge rejected the API token (401). Reconnect in the Forge MCP dashboard." and the dashboard shows the connection as broken. Tests in Task 3 (mapping), Task 10 (tool error + audit `error`), Task 18 (dashboard shows it).
2. **Forge token missing a scope (403)** → the agent is told which action failed and to add the scope to the Forge token, not a generic error. Test in Task 3.
3. **Agent passes an `organization`/`server_id`/`site_id` that doesn't exist or isn't permitted** → clear error, no Forge call for unexposed orgs, denied entry audited. Tests in Task 10 and Task 11.
4. **A `.env` value appears inside a stack trace, URL or JSON in a log** → still masked, and ordinary log lines (timestamps, short words, `production`) are untouched. Test in Task 9.
5. **MCP token revoked mid-session, or a dashboard session cookie used against `/mcp`** → 401; a token without the `mcp` ability is rejected. Test in Task 10.
